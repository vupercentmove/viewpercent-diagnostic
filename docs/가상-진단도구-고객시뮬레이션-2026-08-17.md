## 4. 실완주에서 발견한 프로덕션 결함 (가상 아님 — 실제 관측)

### 🔴 결함 1. AI 코멘트가 진단 결과와 어긋난다

정밀 진단 실완주 결과:
- 판정된 최약 구간: **STAGE 3 쇼핑의 시작 (70점)**
- 화면 헤로: "지금은 '쇼핑의 시작'에서 새고 있어요" ✅
- **AI 코멘트: "실제 구매 결정 단계에서 이탈이 생기고 있네요"** ❌

STAGE 4 구매결정은 **90점(양호)**으로 두 번째로 높은 점수다. AI가 진단이 짚지 않은 단계를 지목했다.
같은 화면에서 헤로와 AI 코멘트가 다른 단계를 말한다.

단계명 전달 배선은 `app/api/analyze/route.ts`에서 정본(`stage-meta.ts`)을 쓰도록 이미 고쳐져 있다.
즉 **배선이 아니라 생성 내용 자체의 문제**이며, 현재 가드(수치 날조 차단)로는 잡히지 않는다.

### 🔴 결함 2. 존댓말이 깨진 문장이 노출된다

> "결국 당신의 시간도 훨씬 절약될 **거야요**."

- `거야요`는 비문이다.
- **"당신"**은 카피 정본의 호칭("대표님")과 어긋난다.

### 🟠 결함 3. 벤치마크 표현이 한 화면에서 두 번 다르게 나온다

빠른 진단 결과 한 화면 안에:
- 상단 히어로: "지금 우리보다 앞서 있는 브랜드가 **약 89%**"
- 1순위 카드: "이 단계는 진단한 브랜드의 **약 95%**가 더 앞서 있어요"

전자는 종합, 후자는 단계별이라 계산 근거는 다르지만 **화면에서는 구분되지 않는다.**
F2가 "대표에게 못 보여준다"고 한 지점이 정확히 여기다.

### 🟠 결함 4. 전 구간 양호인데 "가장 새는 세 구간"이라 말한다

정밀 결과에서 6단계가 **70~100점 전부 양호**로 나왔는데, 화면은 "아래 카드가 가장 새는 세 구간이에요"라며
83점 구간까지 "새는 곳"으로 제시한다. 상대 순위를 절대 표현으로 말하는 구조다.

## 6. 반증 조건 판정

> 반증 조건: 패널 과반이 결과 화면 도달 전에 그만두면 → 문항 수·흐름 설계가 틀린 것

**판정: 미충족 (= 설계는 틀리지 않았다)**

- 타깃 패널 3명(F1·F2·F3) **전원이 결과 화면까지 도달**했다.
- 이탈 위험이 언급된 지점은 문항 수가 아니라 **연속 '아니요' 구간의 정서**(F1)였고, 그마저도 완주는 했다.
- F4는 애초에 타깃 밖이라 이탈 카운트에서 제외.

→ **문항 수·흐름을 줄이는 방향의 개편은 근거가 없다.** 고칠 것은 완주율이 아니라 **결과 화면의 신뢰도**다.

- **대상물**: 뷰퍼센트무브 셀프 진단 도구 (빠른 10문항 / 정밀 27문항)
- **부른 층**: 광고주 (F 즉석 생성 4명) + 실데이터 대조군 (의류업 종사자 3명)
- **만난 가상 고객**: 정미래(34·1인 대표) · 한소영(29·마케팅 담당) · 오정한(41·연매출 30억) · 김하늘(26·CS, 타깃 밖) / 오다슬(31) · 박송이(37) · 노시연(21)
- **세션 전 반증 조건**: 패널 과반이 결과 도달 전 이탈하면 문항 설계가 틀린 것
- **반증 조건 충족 여부**: **미충족** — 타깃 3명 전원 완주. 문항 수 축소는 근거 없음
- **가장 의외였던 반응**: F3 "**10문항은 미끼, 27문항이 본체**로 보여요" — 빠른 진단이 진입로가 아니라 *신뢰를 깎는 구간*으로 읽힐 수 있다는 것
- **그래서 바꾸기로 한 것**: 결과 화면의 **벤치마크 표현 일원화** (89% vs 95%가 한 화면에 공존하지 않게)
- **바꾸는 층위**: **구조** — F2는 "무슨 말인지 모르겠다"가 아니라 "이해했는데 그래서 못 믿겠다"로 막혔다. 문구를 바꿔도 두 숫자가 남아 있으면 같은 거절이 재발한다
- **실제 고객에게 확인해야 할 것**: "결과에서 '앞서 있는 브랜드가 89%'를 보셨을 때, 계속 볼 마음이 드셨나요 아니면 닫고 싶으셨나요?"

## 8. 우선순위 제안

**즉시 (프로덕션 결함 — 가상 아님)**
1. AI 코멘트가 진단 최약 단계와 다른 단계를 지목하는 문제 (결함 1)
2. `거야요` 비문 + "당신" 호칭 (결함 2)

**다음 (신뢰도)**
3. 벤치마크 표현 일원화 (결함 3 — 세션 카드의 결론)
4. 전 구간 양호일 때의 결과 문구 분기 (결함 4)

**검토**
5. 사례 매칭에 여성복·플랫폼 축 반영 (F2)
6. 결과 화면 CTA 성격 버튼 4개 정리 (F3)

⚠️ 4~6은 가상 반응 기반이다. 실제 고객 확인 전에는 가설로만 둔다.

## 9. 후속 조치 결과 (2026-08-17~18 · 문서 보존 시점 기준)

§4에서 관측한 프로덕션 결함 4건은 전부 **코드에서 원인이 확인되어** 수정·배포됐다.
시작할 때 3·4번을 "가상 반응 기반 가설"로 분류했으나, 파보니 둘 다 실제 코드 결함이었다.

| # | 항목 | 확인된 원인 | PR | 상태 |
|---|---|---|---|---|
| 1 | AI 코멘트가 최약 단계와 다른 단계 지목 | `full` 프롬프트가 최약 단계 한 줄만 넘기고 나머지 5단계 점수 미전달 (quick은 6단계 전부 전달) | #21 | 배포·프로덕션 검증 |
| 2 | `거야요` 비문 + "당신" 호칭 | 프롬프트에 호칭·종결 규칙 부재 | #21 | 배포·프로덕션 검증 |
| 3 | 벤치마크 89% vs 95% 혼동 | 히어로의 두 분기 중 `>50` 쪽에만 기준("전체 점수") 표기 누락 → 하위권 사용자에게만 발생 | #22 | 배포 |
| 4 | 전 구간 양호인데 "가장 새는 세 구간" | 절대 표현(`새다`)에 대한 조건 분기 자체가 없었음 | #23 | 배포·프로덕션 양쪽 분기 검증 |

**1번의 안전망**: `lib/stage-guard.ts` 신규 — 최약 단계를 빼고 다른 단계만 지목한 코멘트를 폴백으로 교체하고
`reason: "wrong_stage"`로 어드민 폴백률에 기록한다. 단계명 비교는 공백을 지우고 한다(정본 `구매결정` vs AI `구매 결정`).
⚠️ 배포 후 프로덕션 4회 호출에서 AI가 전부 올바르게 생성해, **가드가 실제 발동하는 경로는 아직 미검증**이다.

### 반증 조건 재확인

세션 전 반증 조건("패널 과반이 결과 도달 전 이탈")은 **미충족**이었다. 타깃 3명 전원 완주.
