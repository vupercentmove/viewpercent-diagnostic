# 진단 언어 원칙 (2026-07-25)

출처: 롱블랙 노트 2056 「인사이트 수업: 일본 1위 광고기획사 마케터의 '숨겨진 본심' 파악법」

## 0. 왜 문구를 바꾸는가

인사이트는 새로운 정보가 아니라 **사람을 움직이는 숨겨진 본심**이다.
좋은 결과 문구는 대표가 읽고 "맞아요, 그게 답답했어요"라고 반응하게 한다.

본심은 완성된 답이 아니라 망설임 속에 있다 — "음…", "그런데…", "사실은…", "원래는…", "솔직히…".
따라서 진단도구는 **대표가 처음 말한 요구를 그대로 받아 적는 도구가 아니라,
그 말이 나오게 된 경험을 되짚어 본심 가설을 세우고 검증하는 도구**여야 한다.

구분:

| 층위 | 정의 | 진단도구에서 |
|---|---|---|
| 니즈 | 쉽게 발견되는 요구 | "광고 효율을 높이고 싶다" — 여기서 끝내면 안 됨 |
| 파인딩스 | 새롭지만 사람을 안 움직임 | 점수·차트만 보여주는 결과 |
| 인사이트 | "맞아요" + 행동이 달라짐 | 목표 지점 |

## 1. 적용한 원칙 6가지

1. **추상적 만족도를 묻지 않는다** — 만족·자각이 아니라 확인 가능한 경험과 행동을 묻는다.
2. **유도 질문을 만들지 않는다** — 원하는 결론을 질문에 심지 않는다. 해석은 결과 화면에서 한다.
3. **망설임이 나타나는 지점을 더 묻는다** — "모름"은 버릴 데이터가 아니라 가장 정보가 많은 답이다.
4. **답변을 반복하지 말고 본질을 재정의한다** — 단, 답변보다 앞서 나가거나 말하지 않은 감정을 단정하지 않는다.
5. **진단과 영업을 분리한다** — 경험 → 패턴 → 문제 재정의 → 필요한 역할 정의가 끝난 뒤에만 해결 구조를 연결한다.
6. **결과는 단일 결론이 아니라 응답 유형별로 분기한다** — 모든 대표를 같은 결론으로 몰지 않는다.

## 2. 이번에 바꾼 것

### 2.1 기본 10문항 (`lib/questions.ts`)

`id` · `answerType` · `stageId` · REVERSE_YN 방향은 전부 그대로 두고 문구만 교체했다.
스코어링·벤치마크 이력에 영향 없음.

| id | 전 | 후 | 고친 이유 |
|---|---|---|---|
| q1a | 광고비는 올렸는데, 매출은 그만큼 안 따라온 적 있나요? | 최근 3개월 안에, 광고비를 늘린 달에 매출이 그만큼 늘지 않은 적이 있나요? | 시점 한정 — "적 있나요"는 사실상 전원 "예"라 변별력이 없었음 |
| q1b | 광고 성과가 하루하루 들쭉날쭉한 편인가요? | 지난달 광고 성과가 오르내린 이유를, 대표님이 설명하기 어려웠던 날이 있었나요? | 인상 평가("~편인가요") → 판단 근거의 유무라는 사실 |
| q2a | 처음 봤을 때 "여기 뭔가 다르다"고 느낄 수 있나요? | 주변에 "우리 브랜드가 어떤 곳 같아?"라고 물었을 때, 의도한 답이 돌아오나요? | 대표가 고객 마음을 대신 채점하던 문항 → 실제로 겪은 일 |
| q3a | 사는 이유가 "예쁘니까"를 넘어서는 게 있나요? | 최근 후기나 문의에서, "예쁘다" 말고 다른 이유로 샀다는 말을 본 적 있나요? | 추상 판단 → 열어보면 확인되는 근거 |
| q3b | 고객의 걱정을 상세페이지에서 **충분히** 풀어주고 있나요? | 고객이 CS나 DM으로 가장 자주 묻는 질문이, 상세페이지에 이미 답으로 적혀 있나요? | '충분히'는 자기채점. 관찰 가능한 사실로 |
| q4a | 얼마나 되는지 **알고 계신가요**? | 장바구니에 담고 결제하지 않는 고객 비율을, 지금 바로 열어서 확인할 수 있나요? | 자각 여부 → 실제로 가능한 행동 |
| q4b | 나가는 고객이 있을 수 있다고 **생각해 보신 적** 있나요? | 가장 많이 팔리는 상품에, 사이즈나 체형을 언급한 후기가 5개 이상 있나요? | 생각 여부를 묻던 최악의 문항. 세어보면 답이 나오는 사실로 |
| q5a | 품절돼서 매출을 놓친 적 있나요? | 최근 한 시즌 안에, 잘 나가던 상품이 품절돼 판매를 멈춘 적이 있나요? | 시점 한정 |
| q6a | 다시 오는지 **확인해 보신 적** 있나요? | 첫 구매 고객 중 몇 퍼센트가 다시 왔는지, 지금 숫자로 말할 수 있나요? | 확인 경험 → 지금 답할 수 있는지 |
| q6b | "우리 카테고리는 원래 재구매가 없어" 하고 **넘기신 적** 있나요? | 재구매율은 카테고리가 정하는 거라, 브랜드가 바꾸기는 어렵다고 보시나요? | 유도 + 낙인("넘기신 적"). 체념 신호는 그대로 잡되 견해를 중립적으로 물음 |

### 2.2 심화 문항 (`lib/deep-questions.ts`) — 9개 교체

자기채점 부사('충분히·전략적으로·적극적으로')와 대표가 고객 마음을 대신 평가하던 문항을 사실 확인형으로 교체했다: `d1d` `d2c` `d2d` `d3a` `d3d` `d3e` `d4e` `d6c` `d6d`.

예) d3e "'이 옷을 입으면 이렇게 된다'는 스토리를 전달하나요?" → "상품 사진에 착용 상황(장소·시간·같이 입은 옷)이 드러나 있나요?"

이미 사실 기반이던 문항(`d1a` `d1b` `d1c` `d2a` `d2b` `d3b` `d3c` `d4a`~`d4d` `d5a`~`d5d` `d6a` `d6b` `d6e`)은 건드리지 않았다.

### 2.3 되비춤 (`ECHO_PHRASES`)

전부 다시 썼다. 기존은 답변을 그대로 되돌려주는 문장이었다.

- (전) "광고비를 올려도 매출이 그만큼 따라오지 않는다고 답하셨어요." ← 답변 반복
- (후) "광고비를 늘린 달에 매출이 따라오지 않았다면, 지금 모자란 건 예산이 아니라 그 예산을 어디에 쓸지 정할 근거일 수 있어요."

규칙: 대표가 고른 사실을 받되 **한 겹 다시 정의**하고, 확정 어투 대신 "~일 수 있어요 / ~인 상태예요"로 여지를 남긴다. 말하지 않은 감정("답답하셨죠")은 넣지 않는다.

### 2.4 손실회피 한 줄 (`LOSS_AVERSION_LINE`)

- (전) "지금 흘려보내면 다음 시즌에도 같은 자리에서 새는 매출이에요."
- (후) "이 구조가 그대로면, 다음 시즌에도 같은 자리에서 같은 판단을 하게 됩니다."

"지금 안 하면 손해"라는 압박은 진단을 영업으로 만든다(원칙 5). 상수 이름은 참조처 때문에 그대로 두었으나, 성격은 손실회피가 아니라 구조 인식이다.

### 2.5 빈틈 진단 메시지 (`detectGap`) — 4개 전부 교체

두 가지 문제가 있었다.

1. **대표가 답하지 않은 것을 답했다고 단정** — "광고 효율이 가장 큰 고민이라고 답하셨지만"은 어느 문항에서도 물어본 적이 없다. 문항이 바뀌면서 불일치가 더 커졌다.
2. **성과를 약속** — "먼저 해결하면 같은 유입에서 더 많이 팔 수 있어요", "~해야 장바구니에 담기는 숫자 자체가 늘어납니다"는 진단이 아니라 영업이다.

실제로 답한 내용만 되짚고, 단정 대신 "~볼 수 있어요"로 바꿨다.

### 2.6 하단 CTA 노출 시점 (`components/StickyCtaBar.tsx`)

결과 화면에 들어가는 순간부터 "이 빈틈, 카톡으로 봐드릴게요"가 하단에 고정 노출되고 있었다. 진단을 한 줄도 읽기 전에 영업이 먼저 보이는 구조(원칙 5 위반).

한 화면(viewport의 90%) 넘게 내려본 뒤에 나타나도록 바꿨다. 노출 트래킹(`trackStickyCtaView`)도 마운트 시점이 아니라 **실제로 보인 시점**에 1회 발생하므로, 이제부터 sticky CTA 노출수는 "결과 화면 진입수"가 아니라 진짜 노출수다.

> ⚠️ 기존 `sticky_cta_view` 지표와 시계열이 끊긴다. 배포일 기준으로 나눠서 봐야 한다.

## 3. 결과 유형 6종 분기 — 현재 문항으로 가능한지

**가장 중요한 발견부터.** 제시된 6유형과 현재 진단도구는 **축이 다르다.**

- 현재 도구의 축: **고객 여정 6단계** — 고객이 어디서 돌아서는가
- 6유형의 축: **대표–대행사 판단 구조** — 누가 무엇을 정하는가

두 축은 직교한다. 한 브랜드가 "Stage 3이 가장 얇으면서 동시에 판단공백형"일 수 있다.
따라서 6유형을 기존 Stage 결과에 억지로 끼워 넣으면 **둘 다 흐려진다.**

판정:

| 유형 | 현재 문항으로 가능? | 근거 |
|---|---|---|
| **정보공백형** (판단에 필요한 데이터 부족) | ✅ 가능 | `q1b` `q4a` `q6a` + `d1a` `d1c` `d2a` `d2d` `d6b`가 전부 '데이터를 지금 열어볼 수 있는가'를 묻는다. 별도 지표로 집계만 하면 된다 |
| **구조점검형** (광고보다 상품·콘텐츠·재구매를 먼저) | ✅ 이미 있음 | `detectGap` 패턴 1이 정확히 이것 — 광고를 짚었는데 실제 최약은 다른 Stage |
| **안정운영형** (판단·실행 구조가 비교적 명확) | ✅ 가능 | `calcOverallScore` ≥ 70 이면서 `detectGap`이 null |
| **판단공백형** (보고는 받지만 다음 행동 결정이 어려움) | ❌ 불가 | 대행사 보고를 받는지, 받은 뒤 무엇을 하는지 묻는 문항이 **하나도 없다** |
| **실행공백형** (판단은 되는데 실행 인력 부족) | ❌ 불가 | 인력·실행 리소스 문항이 없다. `icp_content`(콘텐츠 주 1회)가 유일하게 근접하지만 대리 지표로 쓰기엔 약하다 |
| **역할혼선형** (대표–대행사 책임 범위 불명확) | ❌ 불가 | 대행사 관련 문항 자체가 없다 |

→ **3종은 지금 문항으로 판정 가능, 3종은 추가 설계 필요.**
지시대로 억지로 만들지 않았다.

## 4. 추가 설계 필요 (미구현 — 설계안만)

### 4.1 망설임 후속 질문 (원칙 3) — 현재 구조가 정반대

| 경로 | 현재 | 문제 |
|---|---|---|
| 빠른 진단 (`QuizStage`) | "모름" 선택지 **없음** | 망설임을 아예 기록하지 못한다 |
| 심화 진단 (`DeepQuizStage`) | "모름" 선택지 **없음** | 같음 |
| 정밀 진단 (`FullDeepQuizStage`) | "모름" 있음. 단, **2연속이면 그 Stage를 건너뜀** (`quiz-fallback.ts`) | 가장 정보가 많은 지점에서 질문을 멈춘다 |

롱블랙 원리대로면 "잘 모르겠어요"는 **끝내는 신호가 아니라 한 단계 더 들어가는 신호**다.

제안: 2연속 모름 시 Stage를 건너뛰는 대신, 난이도를 한 칸 낮춘 후속 질문 1개를 붙인다.

```
"장바구니 이탈 비율을 지금 열어볼 수 있나요?"  → 모름
   ↳ "그 숫자를 확인해야 할 때, 누구에게 물어보세요?"
      ( 내가 직접 본다 / 대행사에 요청한다 / 확인할 데가 없다 )
```

이 후속 답변 하나가 **4.2의 세 유형을 가르는 최고 신호**다. 두 작업은 같이 설계하는 게 맞다.

### 4.2 판단 구조 문항 블록 (원칙 6의 나머지 3유형)

기존 Stage 문항에 섞지 말고 **독립 블록**으로 두기를 권한다 (축이 다르므로).
정밀 진단의 ICP 문항처럼 3~4문항이면 충분하다. 초안:

| 문항 | 가르는 유형 |
|---|---|
| 최근 광고비를 늘리거나 줄인 결정은 누가 내렸나요? (내가 / 대행사 제안을 받아들여 / 정한 적 없다) | 역할혼선형 |
| 그 결정을 내릴 때 무엇을 보고 정하셨나요? (대행사 보고서 / 내가 따로 보는 숫자 / 감 / 본 적 없다) | 판단공백형 · 정보공백형 |
| 대행사 보고를 받은 뒤, 다음에 뭘 할지까지 함께 제안받나요? (예 / 보고만 받는다 / 보고를 안 받는다) | 판단공백형 |
| 지금 방향은 정해졌는데 손이 모자라 못 하고 있는 일이 있나요? | 실행공백형 |

⚠️ 원칙 2 유지 — "대행사가 광고비만 늘리려 해서 답답하셨나요" 같은 문항은 넣지 않는다.
**광고비를 늘리는 것이 항상 잘못이라는 전제도 쓰지 않는다.** 사실만 고르게 하고 해석은 결과에서 한다.

### 4.3 본심 가설은 아직 가설이다

> "대표님이 원하는 건 관리 화면을 대신 봐주는 사람이 아니라, 광고비를 늘릴지 줄일지 함께 책임지고 판단할 사람입니다."

이 문장은 **검증되지 않은 고객 본심 가설**이다. 모든 사용자에게 확정된 진단처럼 출력하면 안 된다.
4.2 문항의 답변이 실제로 그 상태를 가리킬 때만 결과 문구로 도출되어야 한다.

검증 방법: 이 문장을 본 대표가 "맞아요"라고 반응하고 **행동이 달라지는지**(카톡 문의에서 이 표현을 다시 쓰는지)를 본다.
반응이 없으면 인사이트가 아니라 파인딩스다.

## 5. 이번 수정의 목표

진단을 마친 대표가 "서비스를 팔려고 질문하는구나"가 아니라,
**"내가 광고를 맡기고도 왜 계속 직접 판단해야 했는지 이제 알겠다"**고 느끼는 것.

3장 기준으로 현재 도구는 아직 그 문장까지 못 간다. 4.1과 4.2가 남은 거리다.
