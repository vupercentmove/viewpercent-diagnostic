## 1. 배경 & 문제

현재 앱 흐름: `intro → quiz(기본 10문항) → result → (선택) deep-quiz(가장 약한 1단계 심화) → deep-result`.

빠른 진단(10문항)은 라이트 유저에겐 맞지만, **이미 콘텐츠·광고로 여기까지 스스로 온 "정체기 대표"**에겐 *"이미 아는 얘기"*로 느껴져 신뢰·전환이 약하다. 이들은 답답·절박한 상태로 이것저것 시도해봤고, 더 깊은 진단을 원한다.

## 2. 목표 / 비목표

**목표**
- 인트로에서 **빠른 진단 / 정밀 진단** 모드를 선택하게 한다.
- 정밀 진단 = 6단계 전 세부영역(~28 심화문항)을 도는 **풀 심화**로, 진지한 예비고객에게 *"제대로 받았다"*는 신뢰를 주고 **카카오 상담 전환**을 높인다.
- 결과는 점수판이 아니라 **성희님 톤의 개인화 코칭**으로 읽히게 한다.

**비목표 (이번 범위 밖)**
- 빠른 진단(기존) 로직·문항 변경 — 그대로 유지.
- 결제·회원·인증 도입. 어드민 고도화(태깅 UI)는 후속.
- 심화 문항 자체의 내용 개편(문항 추가는 최소).

## 3. 타깃 페르소나 (정밀 모드가 겨냥하는 "한 명")

- 월매출 **3억 이하**, 이제 막 시작한 대표는 아님 — 콘텐츠로 고객을 쌓아온 사람.
- **정체·하락기**에 진입. 광고비 최소 **월 300만원+**, 영상 콘텐츠 지속 제작, **고객이 귀한 줄 아는** 대표.
- 감정: **답답·절박.** 자료 찾아 이것저것 시도해봄. **노력多·데이터少** — 어디서 새는지 숫자로 본 적 없음.
- 정밀 진단의 진짜 가치 = 성능 자랑이 아니라 **막연한 답답함에 '구조와 언어'를 주는 것.**
- (근거) 계약 기준 "우리 얘기를 귀하게 들어주는 곳" / CRM 1순위 "단골 관리·러닝 되는 곳"(이미 실행 중) / 거를 기준 "억만금 줘도 자기 일 던지는 곳".

## 4. 사용자 흐름

```
intro (모드 선택: 빠른 진단 / 정밀 진단)
  └─ 정밀: full-deep-quiz (6단계 순차, STAGE n/6)
        └─ analyzing → full-result (집계 레이더 + 단계별 개인화 코칭 + CTA)
  └─ 빠른: 기존 흐름 (quiz → result → 선택 deep) — 변경 없음
```

- `mode: "quick" | "full"` 상태 추가.
- 정밀은 초급 10문항을 **건너뛰고** 바로 6단계 심화로 진입. 6각 레이더는 심화답변 **집계**로 유지(§8).

## 5. 핵심 설계 원칙 — 성희님 정본 + 세션 반영

### 5.0 톤 (정본 — 모든 텍스트 필수)
- **말투 정본:** "월매출 1억 여성패션 대표 한 명에게, 가이드형 전문가가 **차분하게 구조를 짚어주는** 목소리." 스타 과시·대행사 영업 톤 금지.
- **성희님 8원칙 필수 통과:** ①핵심행동 먼저 ②부정어 연속 금지 ③톤 급상승 금지 ④공감 먼저 ⑤인과로 설득 ⑥행동-결과 연결 ⑦질문 후 바로 이유 ⑧일반론 금지.
- **CTA 정본:** "이 빈틈, 카톡으로 봐드릴게요" + 행동-결과 연결("카톡 주시면 지금 구조에서 새는 지점을 짚어드립니다"). *기존 캡처의 "카카오로 상담 시작"은 이 정본으로 교체.*
- **전환 톤:** "증명"(잘난 척)이 아니라 **"공명"**. "안개를 걷어주는" 감정.

### 5.1 결과 = 인과+트리거 개인화 문장 (세션 ①, ⭐핵심)
판정문("구매결정 38점")에서 멈추지 않는다. 응답 입력값을 되받아 **3연 구조**로 출력:
> [너는 지금 이렇게만 하고 있지] → [그래서 여기가 막혀 — 인과] → [X만 해도 기대 효과 이만큼 — 트리거]
- 근거: 성희 *"인과관계에 올려서 꼭 해야 되는 행동의 트리거를 줘야."*
- Q5(어느 단계 세게) 답: 고정 단계가 아니라 **응답자별 자동 약점 + 개인화 문장.**

### 5.2 결과 섹션 두괄식 — "왜 물었나 + 할 행동" 먼저 (세션 ③)
각 결과 섹션 서두에 **질문 의도 1줄 + 행동 1줄.** `무조건/꼭` 남발 금지(로직 없어 보임). 근거: 성희 *"내가 왜 이 질문을 했는지 바로 알려줘야."*

### 5.3 필터 vs 깔때기 = 판정-표현 분리 (세션 ④, ⭐잭 논리)
- **판정(필터):** 행동 증거 문항(광고비 실지출 규모·콘텐츠 지속 제작)으로 **ICP 여부 내부 판정** → 어드민에 태깅. 근거: 잭 *"좋다고만 하고 안 할 사람 = 헬스장 안 가는 사람."*
- **표현(깔때기):** 결과·CTA 워딩은 **탈락 구간도 부정어 없이 긍정 리프레이징.** 근거: 성희 *"거르더라도 워딩 리프레이징."*
- → 지금은 깔때기(리드 다 받기), 필터 지능은 데이터로 미리 심어둠. 리빌드 없이 후속 전환.

### 5.4 감정·비전 문항 + 되비춤 (세션 ⑤ = "내 편" 인터랙션)
- 정밀 진단에 **비전 질문 1개**: "매출이 성장하면 뭘 하고 싶으세요?" (자유/선택 혼합).
- 결과에서 **그 답을 되비추는 공감 장치**: "○○ 하고 싶다고 하셨죠 — 그러려면 지금 새는 여기부터."
- 근거: 성희 *"interaction 없으면 나를 이해해준다는 느낌 못 받아."* → 일방향 결과지의 한계 극복. "내 편이 생겼다"의 진단 내 구현.

### 5.5 모름 연쇄 fallback (세션 ⑥ + 잭 추가) ⭐신규
- 풀모드 심화 UI(`FullDeepQuizStage`)에 **"잘 모르겠어요/아직 안 해봤어요"** 응답 옵션 추가.
  - **⚠️ 이 옵션은 `lib/deep-questions.ts` 데이터가 아니라 `FullDeepQuizStage`에서만 렌더한다.** deep-questions는 빠른 진단의 기존 `DeepQuizStage`와 공유하는 데이터이므로, 모름 옵션을 데이터에 넣으면 빠른 진단 심화에도 노출돼 §2 비목표(빠른 진단 불변) 위반. → 모름 옵션·fallback 로직은 **풀모드 UI 계층에서만** 주입한다.
- **한 단계 안에서 '모름'이 2회 연속되면** → 그 단계의 남은 심화 문항을 **더 파지 않고 중단**, **"설명 먼저" 카드로 전환**(그 영역이 왜 중요한지 + 잘하면 어떤 모습인지, 8원칙 통과 가이드 톤) → 다음 단계로.
- 카운터는 **단계별로 독립 관리**하고, 중간에 실제 답변(모름 아님)이 나오면 **연속 카운트 리셋**. (다음 단계 진입 시 0에서 시작)
- 근거: 잭 *"질문해도 모른다만 남기는 사람들은 계속 쭉 얘기하게 돼버린다."* (성희 세션 원문)
- 부수 효과: **완료율 방어**(모르는 사람을 갈지 않음) + **콘텐츠/코칭 소재**(대표들이 제일 모르는 영역 = 지표로 수집).

### 5.6 저장 = CRM 자산 시드 (세션 ⑤ 후반)
Supabase 저장을 "어드민 통계"가 아니라 **팬덤 자산화 CRM의 첫 데이터 수집 지점**으로 설계. 감정/비전 답·ICP 태그·모름 영역을 상담·팔로업 자산으로 보존. 근거: 성희 *"목적이 관리가 아니라 자산."*

## 6. 컴포넌트

**신규**
- `lib/full-deep-scoring.ts` (순수·테스트) — 심화답변 → 단계별 점수 집계 + 약점 + subArea 강약 + 모름 집계.
- `lib/quiz-fallback.ts` (순수·테스트) — 연속 '모름' 카운트 → fallback 전환 판정.

## 7. 데이터 모델 (Supabase)

- 진단 레코드에 **`diagnostic_mode: "quick" | "full"`** 컬럼 추가.
- 정밀 레코드 저장 필드: 단계별 subArea 답변, 집계 단계점수, 감정/비전 답, **ICP 시그널(광고비·콘텐츠 지속)**, `icp_flag`(내부 판정), 모름 영역 목록.
- **벤치마크 이중집계 방지:** 기존 규칙(base 분포 = `deep_stage_id IS NULL` 행만) 준수. 정밀 레코드는 별도 mode로 분리 집계.
- (후속) 어드민에서 `icp_flag`·모름 영역 세그먼트 조회.

## 8. 스코어링 (집계 레이더 + 모름 처리)

- 단계 점수 = 그 단계 subArea 답변 평균(0~100). 6단계 점수 → `RadarChart` + `StageScoreList`.
- **모름 처리:** '모름'은 0점으로 뭉개지 않는다. 별도 `unknown`으로 기록. 모름 비중 높은 단계는 레이더에서 **"탐색 필요"**로 표기(허위 저점 금지) + 결과는 "아직 안 한 영역, 여기부터"(긍정 리프레이징, §5.3).
- 약점 단계 = 측정된 단계 중 최저. 개인화 문장(§5.1)의 입력.

## 9. AI — `/api/analyze` 풀모드

- 풀모드 프롬프트 변형: 6단계 점수 + 약한 subArea + 감정/비전 답 + 모름 영역을 입력.
- **출력 강제 구조:** 각 코멘트는 §5.1의 **[되받기]→[인과]→[트리거]** 3연 + 8원칙 통과. `무조건/꼭` 금지.
- 모델: 기존 Claude(Haiku 4.5) 유지. **실패 시 정적 폴백 템플릿도 §5.1 [되받기→인과→트리거] 3연 구조 + 8원칙을 그대로 적용한다** — AI 성공/실패와 무관하게 결과 톤·구조가 일관돼야 한다. 폴백은 응답 입력값(약점 단계·subArea·모름 영역)으로 슬롯을 채우는 결정적 템플릿으로 구현.

## 13. 결정된 것 / 열어둔 것

**결정:** 진입=인트로 모드선택 / 범위=풀 심화 6단계 / 결과=집계 레이더 유지(A안) / 결과 세부 카드=약점 2~3단계 펼침 + 나머지 접힘 / 중간 이탈=단계별 저장으로 "여기까지 결과" 허용 / 톤=성희 8원칙·정본 CTA / 모름 연쇄 fallback 채택.

**열어둔 것:** 비전 질문의 자유입력 vs 선택형 비중 / 모름 fallback "설명 카드" 문구 세부(구현 시 copy-writer + 8원칙 검수) / 어드민 ICP 태깅 UI 시점(후속).
